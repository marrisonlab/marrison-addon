Uno o piu asset non hanno header cache sufficienti.

PHP puo essere servito da Apache mentre Nginx distribuisce gli asset. Solo la verifica degli header pubblici conferma la cache effettiva.

Impostazioni
Abilita Browser Cache	

Spegnendo il modulo vengono rimosse solo le regole Marrison da .htaccess. Le direttive Nginx inserite dal sistemista restano attive e vanno rimosse manualmente. Le impostazioni restano salvate.


TTL asset versionati	

Default: 7 giorni. ?ver= identifica una versione, ma il TTL lungo e sicuro solo se l URL cambia ad ogni modifica.


TTL asset non versionati	

Default prudente: 7 giorni. Non usa immutable per non bloccare asset senza cache busting affidabile.


Immutable	 Aggiungi immutable solo agli asset versionati o hashati

Default disattivato. Abilitalo solo dopo aver verificato il cambio URL per CSS Elementor, immagini rigenerate e altri file aggiornabili.

Versioning e cache busting

Il versioning degli asset WordPress (?ver=...) viene mantenuto. Quando la versione cambia, cambia l URL e il browser scarica automaticamente la nuova risorsa.

Il modulo non rimuove query string, non altera handle WordPress e non applica regole a HTML, REST API, AJAX, wp-admin, login, checkout o altre risposte dinamiche.

Configurazione server

Su Apache 2.4 o server compatibili Marrison gestisce un blocco .htaccess isolato e idempotente con mod_headers. Le regole scritte richiedono una verifica degli header reali; le politiche Cache-Control gia presenti vengono conservate.
